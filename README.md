## 原创世界与玩法

这是公共法律失效、私营安保与算力许可取代公共秩序的时代。Token 是游戏内计算、身份验证、义体维护和交通准入的共用资源，不接现实加密货币或真实支付。更强的 AI 是可升级的游戏能力，例如侦察、解密、战斗支援与对话线索分析；实时移动、碰撞和战斗仍由确定性程序控制，不能依赖在线模型逐帧决策。

玩法循环：**接委托 → 探索／潜入／战斗／选择 → 获得 Token、情报与部件 → 升级义体和 AI → 进入更危险区域 → 承担剧情后果**。Token 应形成可理解的取舍：花在战力上，会推迟开启调查线；花在通行权上，会降低后续任务的风险。防止无限刷取、软锁和付费暗示。

首个可玩样板建议限定在一条精细商业街和一栋可进入的建筑：教学委托、一次潜入或正面冲突、一次收集线索、一个需要选择的 NPC、两项义体升级、AI 从一级升至二级、两个分支结果，以及存档／读档。目标是 15–25 分钟可完整体验，失败后可重试，不靠未完成地图延长时长。

剧情方向借鉴的是“边缘人之间的情感代价”和“跨越时间尺度的信息与亲情”这些抽象主题；角色、台词、组织、地点、镜头、音乐和视觉标识必须原创。建议核心谜团：中央塔在向轨道设施购买延迟到达的算力信号，玩家发现自己的任务奖励与城市记忆被同一套账本改写。国风元素融入桥、飞檐轮廓、灯具、纹样与街巷比例，但依然服从同一城市的材料和功能逻辑。成熟向暴力可以有血迹、损伤和后果表现，设置可关闭的血腥程度选项；不以堆砌血腥替代玩法和人物塑造。

## 角色生产流水线：三视图 → Tripo → Blender → 游戏

1. **参考审计。** Codex 读取三视图，记录正／右／背比例、腰线、外套长度、头饰位置、靴高和配色。必要时用 Image 模型补画缺失细节或制作干净的单视图输入，但要人工比对原图；新增图片只是参考。先检验输入是否有姿势、手指或轮廓不一致。
2. **生成前门槛。** `tripo doctor`、账号余额与模型/额度检查通过后，先做 `tripo make ... --for game-pc --dry-run --json`。记录模型、输入视图、候选数和预计资源消耗。CLI 目前已安装并保存登录配置，但 2026-10-17 的 API 连通性检查失败；恢复连通后才能提交生成。不要把密钥写入仓库、日志或提示词。
3. **分件生成。** 优先使用正／右／背视图生成同一角色初稿；若单次生成导致面部、手部、猫耳、高马尾或靴子失真，分别生成这些零件，再在 Blender 中修整和重建。第一轮只取少量候选，截图比较后再决定是否重试。不能保证 Tripo 自动得到一致的可动画人体拓扑。
4. **Blender 修整。** 固定身高 1.69 m 和朝向；修正脸、发际、手指、衣装层次、拉链、口袋、机械头饰与鞋底。重新拓扑与 UV，分离必要的可换装件，补全衣服下可能暴露的身体，处理透明发片与眼睛，制作 PBR 材质、LOD、碰撞代理和标准骨骼。需要的浅纹路烘焙到法线／粗糙度；不要把概念图当立体细节贴在表面。
5. **动作与导出。** 检查 A Pose、骨骼权重、面部基础表情，至少测试待机、走、跑、跳与转身。导出网页可用的 GLB；保存可编辑 `.blend` 母版、来源与生成参数、贴图、检查报告、正／右／背／斜上／斜下 360° 接触表和动作视频。

首版预算建议：玩家近景 LOD0 **不超过 12,000 tris（包括服装、头发、头饰和靴子）**，LOD1 不超过 6,000，LOD2 不超过 2,000；非可见背面和封闭内层不堆面。贴图先试一张 2048² 主材质图集及必要的法线／粗糙度，再根据屏幕尺寸调整纹理密度。当前首屏素材已接近约 5 MB 基线，因此人物模型、贴图和动作必须按需加载；以实际打包大小和浏览器运行结果决定压缩与 LOD，而非宣称达标。

正式入库条件：三视图主要形体可辨认、身高与比例一致；360° 无露空、重面闪烁、明显穿模、反面不可见或错层；动作极限帧无手穿袖、发穿头、靴穿裤；拓扑可变形、UV 无严重拉伸、贴图无明显重复；预算和浏览器帧率通过实测。每项附证据，失败就回到相应制作环节，不用单张正面渲染替代验收。

## 建筑与场景生产流水线

建筑先选择现有样板街区作为质量基线。Blender 制作道路、墙、门窗、楼层与碰撞模块；Tripo 用于需要独特轮廓的招牌、雕塑、机械装置、国风装饰或重点建筑初稿，不让生成结果直接占据可走道路和入口。每栋建筑按楼体、入口、窗框、屋顶、招牌和室内可见部分分件，使场景配置可以重排或替换。可透视的门窗要有墙厚和必要的室内几何。完整检查正面、背面、左右、俯视与玩家街道视角；修正穿模、重面、悬浮、错误碰撞和贴图密度。游戏版另制 LOD 与远景代理，给出逐栋 tris、贴图大小、GLB 大小和场景总开销。沿用现有地面修复、室内碰撞、跳跃与编辑器，不为了新资产破坏这些能力。

## 故事方向草案

此处只定结构和冲突，不定稿角色姓名、对白或任务标题。主角是一名离开特种部队的白马尾士兵，随身 AI 的记忆片段与一桩失踪案有关。商业街委托使她发现 Token 不只购买算力，还决定谁能被系统识别、被安保放行、被记录为“存在”。居住区揭示被切断算力的人如何失去医疗与亲人消息；中央塔则接收来自轨道设施的延迟信息，某些讯息在抵达时已经改变了城市中的决定。

三幕推进：**街区求生与发现异常 → 追查账本和延迟讯息 → 在中央塔选择算力归属**。伙伴关系的代价与迟到的信息是主题，不复用其他作品的人物、情节、独特装置或镜头。国风元素来自旧城区保留下来的街巷、桥、飞檐和光色，而不是突然换一个互不相干的地图。终局至少有两种清楚后果：集中算力使主角和 AI 更强，但少数居民失去许可；公开算力接口使街区获得自主权，但主角必须放弃一项重要个人目标。两条路线都应在游戏过程里提前埋下证据，避免结尾才突然给按钮。

主角与随身 AI 的关系是故事轴心：机械猫耳设备携带一段被删改的旧行动记录，AI 升级后能读出更多内容，却会越来越依赖中央塔供给的 Token。样板店的委托人知道这段记录的来源，但并非全知的解说员；居住区的居民则证明“失去 Token”不只是贫穷，而是无法通过门禁、医疗和公共记录确认身份。中央塔的档案员相信集中控制能防止算力战争，有自己的理由，不能只是一个等着被击败的反派。

| 幕与区域 | 玩家实际要做的事 | 发现与关系变化 | 给下一幕留下的条件 |
| --- | --- | --- | --- |
| 第一幕：商业街 | 在可进入的样板店找回存储芯片和收据；决定交还委托人或出售资料 | 收据记录了已消失居民的 Token 扣款；AI 识别出失踪旧队员的签名 | 获得第一笔资源，打开居住区委托 |
| 第二幕：居住区 | 查访当事人、追踪中继设备；选择保护居民或交换线索 | 失踪名单不是死亡名单，而是被推迟确认的身份；一条多年以前发出的远端讯息最近才被交付 | 找到中央塔账本入口；AI 二级可读更多，但不是通关必需 |
| 第三幕：中央塔 | 取得账本证据，在安保压力下决定公开或封存接口 | 主角查明旧队员曾试图留下公开证据，塔方为了维持秩序扣留讯息 | 两个明确不同的街区与人物结局 |

延迟讯息来自遥远中继设施的长期存储和人为扣留，**不是随意的时间旅行或地球轨道上的夸张相对论效应**。它的作用是让主角面对“终于收到重要消息，但发送者已经无法回答”的情感事实。结局之前要让玩家至少两次实际使用 Token 救人或增强自己，这样最后的资源选择才有体验依据。可追加第三种艰难结局，但必须由早期线索与支线成本支撑，不能成为无代价的完美选项。

成熟向冲突可以表现受伤、血迹和暴力后果，提供减弱显示的选项。首个可玩样板先验证任务与人物关系，不把血腥内容当成唯一卖点。剧情对白、正式称谓和结局文案在实现前另行审稿。

## 本机环境备注：Windows 上推送 GitHub 的 TLS 问题

自 2026-10-28 起，本机 Windows 的 schannel（`git` 与 `curl` 默认使用的 TLS 后端）无法与 `github.com` 完成握手，直接 `git push` 会报：

```text
fatal: unable to access 'https://github.com/…': schannel: failed to receive handshake, SSL/TLS connection failed
```

同一时刻用 .NET 栈访问是正常的（`Invoke-WebRequest https://github.com` 返回 200），`*.github.io` 也一直可访问，所以**这不是网络被封，也不是仓库权限问题**，只是 schannel 这一条 TLS 路径坏了。

已验证的绕过方式：改用 Git for Windows 自带的 OpenSSL 后端，并显式指定它的 CA 证书。

```powershell
git -c http.sslBackend=openssl `
    -c "http.sslCAInfo=D:\Program Files\Git\usr\ssl\certs\ca-bundle.crt" `
    push origin main
```

- `ca-bundle.crt` 的位置随 Git 安装路径变化，一般在 `<Git 安装目录>\usr\ssl\certs\`；找不到时用 `where git` 反推安装根目录。
- 只在网络或系统证书环境修好之前需要这么写；如果 `git push` 恢复正常，可以省掉这两个参数。
- 这条只影响推送，不影响 `git status` / `git log` / `git diff` 等本地操作。
