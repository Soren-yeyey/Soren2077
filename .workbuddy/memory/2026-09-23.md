## 根因诊断（代码级，已核对 `index.html`）

### 「移动机械」

1. **`transition: left .7s ease-in-out, top .7s ease-in-out`（第 103 行）时间固定 700ms，与距离无关** → 点近处 3% 像瞬移，点远处 80% 像飞。真人走路速度应与距离成正比
2. **`ease-in-out` 是对称曲线** —— 起步慢/中段快/收步慢；真人走路是"起步加速 → 匀速 → 收步减速"，缺少分层缓动
3. **left 与 top 各 0.7s 同时插值 → 斜向移动实际速度是水平方向的 √2 ≈ 1.41 倍**。斜着走总比直着走快
4. **没有朝向** —— 角色是**单张背对镜头**的立绘，往左/往右都是同一张图，方向信息完全丢失。这是"机械感"最强的一条（棋子被推着走）
5. **没有步态、没有接触阴影** —— PRD 第 6 节 B 部分已砍「行走动画」，所以是"整张立绘平移"；脚下也无随位置变化的投影
6. 附带：`left/top` 是布局属性，每帧触发 layout + paint，低端机可能掉帧（**尚无实测证据，不下结论**）

### 「画面一般」

1. **角色"贴"在背景上** —— 角色是独立打光的剪影，背景是洗衣店实拍感光，两者光位/色温/景深不接；缺一层"大气"（雾 / 雨丝 / 光晕）把前后景粘起来
2. **没有透视缩放** —— y 从 58% 走到 90%，角色尺寸**一点不变**。走近镜头应变大，这一项缺失 → 空间感崩塌
3. **机位不动** —— 单机位单张图，无视差、无推拉
4. **画面是静态的** —— 除光圈呼吸外无任何持续动效：洗衣机不转、贩卖机灯不闪、雨不落

## 用户报「网页显示出错」→ 根因：localhost 解析成 IPv6，服务只绑了 IPv4

**症状**：用户打开 `http://localhost:8000/` 打不开（我这边无头 Chrome 一直正常 → 典型「我这边好、你那边没好」）。

**根因（实测）**
- 本机 `socket.getaddrinfo('localhost')` → **`('::1', 8000, ...)`，优先 IPv6**
- 我起的服务是 `--bind 127.0.0.1`（**仅 IPv4**）
- `http://127.0.0.1:8000/` → HTTP 200 ✓ ；`http://[::1]:8000/` → **HTTP 000** ✗
- 无头 Chrome 会 Happy-Eyeballs 回退到 IPv4，所以**我的自动化测试全绿，用户全红**

**解法（已验证）**：`python -m http.server 8000 --bind ::`
- 本机 Python 3.13 下 `--bind ::` 是**双栈**：netstat 同时出现 `0.0.0.0:8000` 与 `[::]:8000`
- 验证：`localhost:8000` **HTTP 200**、`127.0.0.1:8000` **HTTP 200**（两个都通）
- 附带好处：手机走局域网 IPv4 也走同一条命令，**不再需要 `--bind 0.0.0.0`**

**已同步文档**：`RUN.md` 第二节主命令加 `--bind ::` + 解释小字；第六节手机那节把 `--bind 0.0.0.0` 换成 `--bind ::`；第十节排错表加一行「浏览器说无法访问 → 先看是否漏了 `--bind ::`，换 `127.0.0.1` 能打开即可确认」。

**教训（重要）**：**验证必须用用户实际会用的地址**。我一直用 `127.0.0.1` 或无头 Chrome 测，等于绕开了用户真实的失败路径。以后交付本地页面，**通信地址一律以 `localhost` 为准做实测**。

## 3B 朝向镜像 —— 已完成，未提交（Day 9 第二步，17:2x）

### 关键技术选择

用**独立的 `scale` 属性**（`scale: var(--face, 1) 1`）做翻转，**不是**往 `transform` 里塞 `scaleX()`。

原因：`#playerHome` 挂着 `animation: idleFloat`，而 `idleFloat` 的 keyframes **整个覆盖 `transform`** —— 塞进 transform 会被动画吃掉，永远不生效。`scale` 是 CSS 独立变换属性，动画不碰它，两者可以共存。

独立变换属性的合成顺序是 **translate → rotate → scale → transform**，所以 `scale` 先围绕元素中心镜像、再执行 `transform: translate(-50%, -100%)` 定位 → 镜像左右对称、**"脚底那一点"对齐的定位完全不受影响**（截图实证：角色在 15% 处站定，位置没跑偏）。

### 实现

- CSS `#playerHome` / `#player` 各加一行 `scale: var(--face, 1) 1;`（默认 1 = 朝右）
- JS 新增 `setFacing(el, dx)`：只看**横向**位移；`|dx| < 1.5%` 直接 return（原地挪一下不该转身，否则左右抖）
- 调用点两处：`renderPlayer()` 与 `renderHomePlayer()`，且都必须在旧坐标被覆盖前算出 dx

## 第 3 步 3D：接地阴影（已完成，未提交）

### 做法：必须是独立元素，不能用 drop-shadow

新增 `.p-shadow`（两屏各一个：`#shadow` / `#shadowHome`），椭圆 `radial-gradient`。

**为什么不能省这个元素**：`filter: drop-shadow` 是贴着立绘的不透明轮廓生成的，而且**跟着元素一起动** —— 角色呼吸上浮（1.4%）、走路起伏（1.1%）时它同步升降，看起来像"人背后印了块影"，而不是"踩在地上"。独立元素身上不带任何动画，角色升起来时它留在地上不动，这才叫接地。

角色身上原来那层黑色 `drop-shadow` 因此摘掉，只保留青色光晕。

- `shadowFor`（`WeakMap`，角色 → 它的影子）：所有"改坐标 / 改时长 / 改瞬移标记"的地方都靠它一次处理两方

- `setInstant(el, on)`：复位瞬移时两者一起开关 `no-transition`
- `setWalkDur()` 内部同步给影子设 `--walk-dur`（差一点就会出现"影子先到、人后到"）

### ⚠️⚠️ 顺手抓出并修掉一个 3B 埋下的真 bug（本步最重要的发现）

- **现象**：角色朝左走时（`--face = -1`）整体**右偏 64.7px —— 正好一个身宽**
- **怎么发现的**：影子是"位置真值"（坐标由 JS 明确写入、且它没有 `scale`），拿它和角色的 `rect` 交叉比对才暴露出来。**3B 当时只验了 `--face` 与 `scale` 的值，没验位置，所以漏了**
- **根因**：`scale` 是独立属性，合成顺序是 `translate → rotate → scale → transform` ⇒ 它排在 `transform` **外层**，把 `transform: translate(-50%,-100%)` 的负号**翻成了正号**（-50% 变 +50%）
- **修法**：基础位移从 `transform` 挪到**独立 `translate` 属性**（`translate: -50% -100%`）—— 它在 scale 外层，不受翻转影响；同时 keyframes 里去掉自带的 `translate(-50%,-100%)`
- **附带好处**：`walkBob` 的 `rotate` 现在会被外层 scale 镜像 → 朝左走时身体往另一侧倾，倾斜方向自动跟着朝向走
- **修后实测**：朝右 / 朝左，角色中心恒为 `453.48`，与影子中心偏差 **0**；店内同样偏差 0；走动 32 帧中心偏差 >1px 的帧数 0

### 本步教训

- **验证一个改动时，要验"它会影响到的所有东西"**，不只是它直接暴露的那个属性。3B 改了 `scale`，我验了 `scale` 生效，却没验 `scale` 对**定位**的连带影响 —— 而独立变换属性的合成顺序恰好就是会互相影响
- **让两个独立来源的数据互相对照**是一种很强的验证手段：影子（JS 写入的真值）与角色（渲染结果）本该重合，对不上就一定有一方错了

## 第 4 步 3E：透视缩放（已完成，未提交）—— 3 组收官

### 做法

角色越靠近画面下方（离观众越近）越大。用 **`height` 承载缩放**，而不是 `scale`：

```css
#player / #playerHome { height: calc(26% * var(--p-scale, 1)); }
.p-shadow { width: calc(8.5% * var(--p-scale,1)); height: calc(3.4% * var(--p-scale,1)); }
```

**为什么不用 `scale`**：`scale` 已经被 3B 的镜像占用（`--face`）。若给它加 transition，转身就会变成"压扁到 0 再展开"的动画，很难看。

JS 按**每屏自己的可站立范围**归一化：

```js
const PERSPECTIVE = 0.22;                     // 总幅度 22%，两端各 ±11%
function setPerspective(el, y, walk) {
  const mid  = (walk.minY + walk.maxY) / 2;   // 范围中点 = 原尺寸
  const half = (walk.maxY - walk.minY) / 2;
  const k    = (1 + ((y - mid) / half) * (PERSPECTIVE / 2)).toFixed(3);
  el.style.setProperty('--p-scale', k);
  const sh = shadowFor.get(el);
  if (sh) sh.style.setProperty('--p-scale', k);   // 影子必须同步缩放
}
```

`placeWithShadow()` 加了一个 `walk` 参数，在里面调用它；两个调用点分别传 `WALK` / `HOME_WALK`。

### 三个细节（都是会出问题的地方）

1. **影子必须一起缩放** —— 人变大而影子不变，立刻露出"影子不是他踩的"破绽
2. **transition 要带上 height / width** —— 用同一条 `--walk-dur`，否则"人到了、尺寸还没到"。角色加 `height`，影子加 `width, height`
3. **脚底锚点天然不变** —— `translate: -50% -100%` 的百分比是相对元素自身高度的，改 height 只让角色向上"长"，脚底那一点不动。这正好是想要的效果，不用额外补偿

### 首屏坑

`--p-scale` 是首帧才由 JS 写入的（初始默认 1）。初始化时若不关过渡，开场会看到人物"放大一下"。
→ 在初始化处包一层 `setInstant(player, true) / setInstant(playerHome, true)`，落位后强制重排再放开。

### 五、这一步踩的两个坑（都值得记）

**坑 1｜flex 主轴把 16:9 图拉成了竖的。** 我想做"图固定、只让文字滚"，于是把 `#card` 改成 `display:flex; flex-direction:column`、给图 `flex: 0 0 auto`。结果图立刻变成 **380×460**（手机 309×549）—— 比例从 1.78 掉到 0.83。根因：`flex-basis: auto` 在 **column 方向**上会绕开 `aspect-ratio`，去取图片的**内在高度**。
→ 改回非 flex，文字区用 `max-height: calc(76vh - 240px)` 自己限高。**卡片里放 16:9 图时，不要让它成为 flex 主轴上的项。**

**坑 2｜"能滚"不等于"能读"。** 第一版调完，测出滚动量 75 / 44 / 101px，我本来想"滚两三行可以接受"。但截图一看：**被截掉的正好是每幕最后那句落点句**（"这回我打算让它多转一圈…"）。叙事作品里，最后一句往往是全幕的落点 —— 藏起来就等于没写。
→ 为此把图 380→**320**、卡片 72vh→**76vh**、行高 1.85→**1.7**、段间距 .75em→**.6em**，并把第 ③ 幕从 6 段并成 5 段，做到三幕全部一屏读完（滚动量 0）。

**坑 3（小）**：`#card` 的 `overflow-y: auto` 在内容恰好顶到上限时会多出一条**整卡滚动条**（截图里一条白竖条）→ 改 `overflow: hidden`。

> 数字的账，随手记一下：桌面 720px 窗口下，250 字 + 一张 16:9 图要 **618px = 85.8vh** 才装得下 —— 那会盖住整个游戏画面。所以只能靠"缩图 + 收行高"腾地方，不能靠"把卡片做大"。
