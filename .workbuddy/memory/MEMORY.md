## 已知环境异常（Day 8 发现，已解决）

- **本机 `localhost` 解析成 IPv6 `::1`**，而 `python -m http.server` 默认只监听 IPv4 → 浏览器打开 `http://localhost:8000/` **连不上**（`http://127.0.0.1:8000/` 却能通）。
- **正解**：起服务一律用 **`--bind ::`**。本机 Python 3.13 下它是**双栈**（netstat 同时出现 `0.0.0.0:8000` 与 `[::]:8000`），`localhost` 与 `127.0.0.1` 都通；手机走局域网 IPv4 也走这条，**不再需要 `--bind 0.0.0.0`**。
- **为什么长期没暴露**：无头 Chrome 会 Happy-Eyeballs 自动回退到 IPv4 → **我这边全绿、用户那边全红**。
- **硬规矩**：交付本地页面时，**实测地址一律用 `localhost`**，不要图省事用 `127.0.0.1` —— 后者恰好绕开了用户真实的失败路径。
- 已同步 `RUN.md`（第二节主命令 + 第六节手机节 + 第十节排错表新增一行）。

## 远程查询手段优先级（Day 5 摸清）

1. **`git ls-remote origin refs/heads/main`** —— 最快，查编号用它
2. **`raw.githubusercontent.com/<user>/<repo>/main/<path>`** —— **逐文件探测 HTTP 状态码**（200 = 远程存在，404 = 不存在）。比 API 稳、**不限流**，适合确认"文件进仓库了没"
3. **`api.github.com/.../contents/`** —— 能列目录，但**未登录请求会被限流**（Day 5 实测返回 `API rate limit exceeded for 89.167.172.6`，出口 IP 为代理节点）。连续多次调用后会失效，不要作为首选
4. **不要依赖本地 `origin/main` 引用**（写不进，见 Day 2 异常）
5. **核验一律走纯管道，不落盘**（Day 8 摸清）：沙箱**不允许往项目目录外写文件** —— `curl -o /tmp/x` 与 `-o /c/Users/18730/AppData/Local/Temp/x` 都报 `No such file or directory`（`mkdir` 却成功，很有迷惑性）。正确姿势：`curl -s URL | tr -d '\r' | md5sum | cut -d' ' -f1`、`curl -s URL | tr -d '\r' | grep -c -- "$k"`。落盘探测可以先用它拿 HTTP 状态码：`curl -s -o /dev/null -w '%{http_code}' URL`

> 另一条教训：`curl | grep -c` 在 for 循环里连续调用时可能个别次抖动返回 0。**单次异常要重试一次再下结论**，不要直接报给用户。

> 又一条教训（Day 6 重犯）：**核验用的关键词必须照抄原文**。Day 6 把「**今天**唯一的任务范围」凭记忆写成「**当天**唯一的任务范围」→ grep 无输出，看起来像文件缺内容。且命令用 `&&` 串联时，前一条 grep 无匹配返回 1 会**短路掉后面全部检查**。规矩：**链式检查一律用 `;` 分隔，不用 `&&`**；抽查词直接从文件复制。

> CRLF 差异别误判：本地工作区是 CRLF、Git 里存 LF，所以远程文件的字节数会比本地**少「行数」个字节**（Day 6 实测：本地 5518 / 远程 5448 / 70 行，差 70）。**比对内容要用 `tr -d '\r'` 归一后算 md5**，不要拿原始字节数当不一致的证据。

> 但字节数也不能反着用：Day 8 实测 `index.html` 远程与本地**同为 35647 字节**（相等）。差别取决于 `core.autocrlf` 当时的状态。结论：**字节数相等或相差「行数」都别下结论，一律用去 CR 后的 md5 判定**。

> **代理故障是间歇性的**（Day 8 修正 Day 4 的结论）：Day 8 的 `git push` **一次成功**（`7fddbff..f3c7047`），而前两天 `github.com` 稳定失败。**遇到失败先重试 1–2 次**，再判定为环境故障并请用户换代理节点。

### 3A 走动手感（已完成，已提交）

- 根因：`#player` 与 `#playerHome` 的 transition **写死 `.7s`** → 挪一步和横穿全场同样快慢，速度不随距离变化 = 滑行感
- 解法：时长 = 距离 ÷ 步速，夹在 [0.30s, 3.00s]；`cubic-bezier(.33, 0, .28, 1)`；16:9 舞台要把纵向分量乘 **9/16** 再算距离
- **关键决定**：时长走 **CSS 变量 `--walk-dur` / `--walk-ease`**，不用 `el.style.transition` —— 行内 style 会压过 `#player.no-transition { transition: none }`，把"复位瞬移"弄坏
- `renderHomePlayer(nextX, nextY)` 必须**接参数**：原实现是"先覆盖 homePos 再 render"，距离信息会当场丢失
- 实测证据：同一会话内 0.30 / 0.61 / 0.75 / 1.17 秒四档（改前恒为 0.7s）；`no-transition` 仍为 `0s`

### 3B 朝向镜像（已完成，已提交）

- **必须用独立的 `scale` 属性**（`scale: var(--face, 1) 1`）做翻转，**不能**往 `transform` 里塞 `scaleX()` —— `#playerHome` 的 `idleFloat` 动画会**整个覆盖 transform**，塞进去直接被吃掉
- ⚠️ **独立变换属性的合成顺序是 translate → rotate → scale → transform** ⇒ `scale` 排在 `transform` **外层**，会把 `transform: translate(-50%,-100%)` 的负号**翻成正号** → 朝左走时整个人右偏一个身宽（实测 64.7px ≈ 一个身宽）。**基础位移必须用独立 `translate` 属性**（`translate: -50% -100%`，在 scale 外层不受影响），不能用 `transform`。Day 9 的 3D 步才发现并修掉（用独立影子当"位置真值"交叉比对才暴露）
- `setFacing(el, dx)` 只看横向位移，`|dx| < 1.5%` 不翻（防止原地小挪时左右抖）
- 7 项实测全通过：朝左 `-1 / scale=-1 1`、朝右 `1 / scale=1`、极近与纯上下不翻、店内同样生效、零报错
- ⚠️ **观感有限**：立绘接近正面视角，镜像视觉差异不明显。想要明显的"转身感"需要侧身立绘或姿态变体（→ 2C）

### 3C 步态起伏（已完成，已提交）

### 3E 透视缩放（已完成，已提交）—— 3 组收官

- 做法：角色 `height: calc(26% * var(--p-scale, 1))`，影子 `width/height` 同样乘 `--p-scale`；JS `setPerspective(el, y, walk)` 按**该屏自己的**站立范围归一化写入（范围中点 = 1.0，两端各 ±11%，总幅度 `PERSPECTIVE = 0.22`）
- **不能用 `scale` 做透视**：`scale` 已用于镜像（`--face`），给它加 transition 会让转身变成"压扁再展开"的动画
- transition 必须把 `height`（角色）/ `width,height`（影子）加进去、共用同一条 `--walk-dur` —— 大小与位移要同步到达，否则"人到了、尺寸还没到"
- **脚底锚点天然不变**：`translate: -50% -100%` 的百分比随元素高度走，所以改 height 只让角色向上"长"
- 首屏：初始化时包一层 `setInstant` —— `--p-scale` 首帧才写入，不关过渡会看到人物"放大一下"
- 实测：街景 y=52 / 64 / 76 → `--p-scale` **0.890 / 0.999 / 1.110**，角色高 167 / 187 / 208 px，脚底恒 = `y% × 舞台高`，影子 97 / 109 / 121 px 同步；店内 y=58 / 90 → 0.890 / 1.110 同样正确；零报错
